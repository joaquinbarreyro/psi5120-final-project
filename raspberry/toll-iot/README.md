# Raspberry Pi Edge Application

This directory contains the software executed on the Raspberry Pi used as the
edge device of the electronic toll collection prototype.

The application controls the complete local transaction cycle: vehicle detection,
image capture, image upload to AWS, reception of the cloud authorization result,
LED actuation, and experimental latency logging.

## Running the Application

From the `toll-iot` directory, the main application is started with:

```bash
python src/main.py

src/
Contains the Python source code of the edge application.

The main responsibilities implemented in this directory include:

monitoring the vehicle presence button through the Raspberry Pi GPIO;

controlling the red, yellow, and green LEDs;

capturing images using the USB camera;

uploading captured images to Amazon S3;

communicating with AWS IoT Core using MQTT;

receiving vehicle authorization results from the cloud;

controlling the toll lane state machine; and

recording timing information used in the experimental evaluation.

The application operates using the following basic states:

WAITING – waiting for vehicle detection;

CONSULTING – image captured and cloud authorization in progress;

AUTHORIZED – authorization received and green LED activated;

DENIED – authorization denied and red LED maintained.

config/
Contains configuration files used by the edge application.

These files define parameters required by the application without embedding
them directly in the Python source code.

certs/
Directory used by the application for the certificates required to establish
the secure MQTT connection with AWS IoT Core.

Private keys and device-specific credentials should not be distributed with
the project source code.

images/
Contains images captured by the USB camera during development and experimental
executions.

Each transaction generates an image associated with the corresponding
experimental event before it is uploaded to Amazon S3.

logs/
Contains execution logs and experimental measurements generated by the
application in a csv file.

The experimental results include the latency measurements collected during the
end-to-end tests of the system.


Hardware Interface
The prototype uses the following Raspberry Pi GPIO configuration:

Component	GPIO
Vehicle presence button	GPIO17
Green LED	GPIO27
Red LED	GPIO10
Yellow LED	GPIO9
￼
The physical button emulates a vehicle presence sensor installed in a toll lane.

The LEDs emulate the local signaling/actuation mechanism:

Red: vehicle stopped / authorization denied;

Yellow: cloud authorization in progress;

Green: vehicle authorized.

Execution Flow
The local transaction starts when the vehicle presence button is pressed.

The Raspberry Pi captures an image using the USB camera and uploads it to
Amazon S3. The cloud infrastructure processes the image and publishes the
authorization result through AWS IoT Core.

The Raspberry Pi subscribes to the corresponding MQTT result topic. When the
result is received, the application updates the LEDs according to the
authorization decision.

The transaction ends after the vehicle presence signal is released, returning
the system to the waiting state.

Experimental Measurements
The Raspberry Pi records the local timestamps required to measure the true
end-to-end latency of each transaction.

The end-to-end latency is measured from the physical vehicle detection event
(button press) until the corresponding LED actuation after the cloud response.

Additional timing information is collected for image capture and S3 upload,
allowing the experimental results to distinguish local image acquisition from
the subsequent cloud-processing path.

Platform
The prototype was executed on a Raspberry Pi 3 running Debian Linux and Python.

A USB webcam was used for image acquisition, and fswebcam was used by the
application to capture JPEG images.

The cloud-side components of the prototype are documented separately in the
aws/ directory of the project submission.
